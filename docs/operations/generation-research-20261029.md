# Generation research in admin — 29 October 2026

The owner requested identifiable generation history and the saved user/provider prompts for product research. `/admin/engine/generations` now shows each V1 job's current profile name/email and a 180-character original-request preview. The existing privacy eye masks these values. Its Details dialog reads the full original request and the exact saved canonical provider prompt, request configuration, logo answers, preset/style identifiers, workspace, Brain flags, execution timestamps, usage, estimated USD cost, charged/reserved credits and request identifiers.

The saved V1 job is the source for the historical request/options. The canonical `v1_image_execution` pricing snapshot is scoped to both job and owner; no prompt is reconstructed from current configuration or copied from another execution. Missing traces/usage/profile/history have explicit empty states. Profile name, account credits, membership and workspace name are current values, separately labelled. The per-user count covers retained durable V1 jobs, including failures; it is not a count of successful images or all actions on the site. The view covers maroImazh and maroLogo V1 jobs. Page search covers only the 50 loaded jobs and their request previews, as labelled.

Identity/request enrichment and the new GET `/api/admin/v1/operations/[jobId]/details` require both `generations.review` and `users.view`; existing MFA applies. Under current RBAC only super admins have generation review. Other operations readers retain the existing operational projection. Private responses use no-store and Authorization variation. The list batches two reads and audits the returned job IDs before exposing research data. If enrichment or its audit fails, technical monitoring remains available without enrichment. Details are fetched only on deliberate opening, strictly throttled and audited before delivery; closing/hiding discards the dialog's loaded data. Provider error codes/status are allowlisted; arbitrary provider messages, storage references/URLs, authentication records and metadata are excluded. The existing image resolver is unchanged.

No migration, dependency/environment change, provider generation, financial mutation or new tracking is required. This uses existing retained records; it cannot recover deleted/missing content, historic account-plan snapshots or events that were never recorded. No unrelated user activity, IP/location inference or training pipeline was added.

Validation and recovery evidence is in the adjacent `generation-research-20261029` folder. `baseline-08e4188.zip` preserves the prior source. A rollback reverts only this release on the current production branch after reconciling later changes, preserving compatible schema, customer data, security patches and earlier backups. Live data-query verification prints availability flags only, with no customer text or credentials. Synthetic UI tests exercise the real changed components in both themes at desktop/mobile widths; they do not use a real customer session or run an AI provider request.
